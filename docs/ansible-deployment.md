# Ansible Deployment Guide - HAMK Network Management Lab

## Overview
This lab uses real SSH connectivity for Ansible automation, simulating production environments. All managed nodes run OpenSSH server and support both SSH key and password authentication.

- **SSH key**: Auto-generated by Ansible control node

## Deployment Steps

### 1. Deploy Containerlab Topology
```bash
cd ~/Verkonhallinta/topology
sudo containerlab deploy -t golden.clab.yml
```

This will:
- Deploy all network nodes (routers, clients, servers, monitoring)
- Install OpenSSH server on all Ubuntu/Kali nodes
- Configure SSH to allow root login
- Start Ansible control node and generate SSH keypair
- Install node_exporter on managed nodes

**Wait for deployment to complete** (~2-5 minutes depending on network speed)

### 2. Distribute SSH Keys
```bash
cd ~/Verkonhallinta
sudo bash scripts/ansible-distribute-key.sh
```

This script:
- Waits for Ansible container to generate SSH keypair
- Retrieves public key from `/ansible/keys/ansible_id_rsa.pub`
- Distributes key to all managed nodes' authorized_keys
- Enables passwordless SSH authentication

Expected output:
```
=== Distributing Ansible SSH Key ===
  ✓ SSH key found
  ✓ Public key retrieved
  Installing key to clab-hamk-verkonhallinta-golden-client1... ✓
  Installing key to clab-hamk-verkonhallinta-golden-web1... ✓
  ...
=== Distribution Complete ===
  Success: 8
  Failed: 0
```

### 3. Verify Connectivity
```bash
# From ansible container
docker exec -it clab-hamk-verkonhallinta-golden-ansible bash
ansible all -m ping

# Expected output:
# client1 | SUCCESS => { "ping": "pong" }
# web1 | SUCCESS => { "ping": "pong" }
# ...
```

### 4. Run Test Playbook
```bash
# From ansible container
ansible-playbook /ansible/playbooks/test-inventory.yml

# Or from WSL host (if ansible installed)
cd ~/Verkonhallinta/configs/ansible
ansible-playbook -i inventory.ini playbooks/test-inventory.yml
```

## Authentication Flow

1. **First attempt**: SSH key authentication
   - Ansible uses `/root/.ssh/id_rsa` private key
   - Target node checks `/root/.ssh/authorized_keys`
   - Success → passwordless access

2. **Fallback**: Password authentication
   - If key fails, use `ansible_ssh_pass=Hamk2024!`
   - Defined in inventory group vars
   - Useful for initial setup or debugging

## Security Notes

⚠️ **Educational Environment Only** ⚠️

This lab configuration:
- Enables root SSH login (not recommended in production)
- Uses simple passwords (production should use strong passwords)
- Disables host key checking (production should verify)
- Shares credentials in plaintext (production should use Ansible Vault)

**Production Best Practices:**
- Disable root SSH login, use sudo
- Use SSH keys only (disable password auth)
- Enable host key verification
- Store passwords in Ansible Vault
- Use separate credentials per environment
- Implement SSH certificate authority
- Enable fail2ban or similar for brute-force protection

## Cleanup

### Destroy Topology
```bash
cd ~/Verkonhallinta/topology
sudo containerlab destroy -t golden.clab.yml
```

### Reset SSH Keys
```bash
# In ansible container, regenerate keys
docker exec clab-hamk-verkonhallinta-golden-ansible rm -f /root/.ssh/id_rsa*
docker exec clab-hamk-verkonhallinta-golden-ansible ssh-keygen -t rsa -b 4096 -f /root/.ssh/id_rsa -N ""

# Re-distribute
sudo bash ~/Verkonhallinta/scripts/ansible-distribute-key.sh
```
