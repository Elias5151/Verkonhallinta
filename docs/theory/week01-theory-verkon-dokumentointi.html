Verkon dokumentaatio

Dokumentaatio on olennainen osa verkon ylläpitoa. Ilman ajantasaista ja hyödyllistä dokumentaatiota verkon hallinta muuttuu nopeasti vaikeaksi: vianetsintä hidastuu, muutosten vaikutukset jäävät epäselviksi ja ympäristön ymmärtäminen riippuu yksittäisten henkilöiden muistista.

Verkon dokumentoinnin peruskohteita ovat:

  • fyysinen topologia
  • looginen topologia
  • laitetiedot ja sijaintitiedot
  • konfiguraatiotiedot
  • baseline ja suorituskykydata
  • muutoshistoria ja ylläpitotiedot

Hyvä dokumentaatio toimii yhtenä verkon ylläpidon tukipilarina: se auttaa suunnittelussa, vianetsinnässä, muutoksissa ja turvallisuustyössä.

Fyysinen ja looginen dokumentointi

Verkko voidaan kuvata kahdella eri tasolla:

  • Fyysinen dokumentointi: kertoo, missä laitteet sijaitsevat ja miten ne on kytketty toisiinsa fyysisesti.
  • Looginen dokumentointi: kuvaa verkon rakennetta ja toimintoja, esimerkiksi VLANit, reititys, IP-verkot, segmentit ja järjestelmärajapinnat.

Esimerkiksi fyysinen dokumentaatio voi sisältää tietokonehuoneen, kaapeloinnin ja porttikytkennät, kun taas looginen dokumentaatio kuvaa, miten verkko toimii eri palvelujen ja segmenttien välillä.

Verkon topologiaa kuvataan usein diagrammeina tai kaavioina. Tyypillisiä työkaluja ovat esimerkiksi diagrams.net, SolarWinds Network Topology Mapper ja erilaisten kuvailujen yhteydessä myös Containerlab.

Laitetiedot ja informaatiolehtipohja

Dokumentaation on sisällettävä laitteen perustiedot, kuten:

  • laitteen nimi
  • tyyppi ja valmistaja
  • malli
  • IP-osoitteet
  • toimiala/verkko
  • käyttöpaikka ja fyysinen sijainti
  • ylläpitäjä tai vastuu
  • konfiguraatiotiedot

Monet organisaatiot ylläpitävät laitteen tietoja inventaario- tai informaatiolehtinä. Tällainen tietokanta tai dokumentti helpottaa standardointia ja viitetietojen hallintaa.

Baseline-ajattelun perusteet

Verkon baseline-ajattelu tarkoittaa verkon normaalin toimintatason kuvaamista. Baseline auttaa vastaamaan kysymyksiin:

  1. Kuinka verkko toimii normaalisti?
  2. Mitkä verkon osat toimivat kriittisesti?
  3. Miksi verkko ruuhkautuu tai heikkenee tietyissä tilanteissa?
  4. Mihin muutoksiin kannattaa keskittyä?

Baseline voidaan rakentaa mittaamalla esimerkiksi:

  • liitäntien käyttöaste
  • suoritinkäyttö
  • pakettihäviöitä
  • latenssia ja virheprosentteja

Baseline muodostaa vertailupohjan, jonka avulla voidaan tunnistaa poikkeamat ja arvioida muutosten vaikutuksia.

Moderni verkkodokumentaatio

Perinteisesti verkkodokumentaatio on koostunut verkkokaavioista, laiteluetteloista ja konfiguraatiotiedoista. Nykyaikaisessa verkonhallinnassa dokumentaatio nähdään kuitenkin osana infrastruktuuria. Dokumentaatio tallennetaan versionhallintaan, sitä päivitetään jatkuvasti ja sitä voidaan tuottaa osittain automaattisesti.

Dokumentaation tavoitteena ei ole ainoastaan kuvata verkkoa, vaan mahdollistaa verkon tehokas ylläpito, kehittäminen, valvonta ja vianratkaisu.

1. Git ja versionhallinta

Git on hajautettu versionhallintajärjestelmä, jonka avulla voidaan seurata tiedostojen muutoksia, palata aiempiin versioihin ja tehdä yhteistyötä useiden käyttäjien kanssa. Git on keskeinen työkalu myös dokumentaation hallinnassa.

Git mahdollistaa:

  • kaikkien muutosten seurannan
  • edellisen version palauttamisen
  • muutoksen tekijän tunnistamisen
  • yhteisen dokumentaation ylläpitämisen usealta käyttäjältä
  • vertaisarvioinnin ja pull request -prosessin

Verkkodokumentaation hallinta ilman versionhallintaa johtaa helposti vanhentuneisiin tiedostoihin, kaksoiskappaleisiin ja epäselviin muutoksiin.

2. Markdown

Markdown on kevyt merkintäkieli, jolla dokumentaatiota voidaan kirjoittaa helposti luettavassa ja versionhallittavassa tekstimuodossa. Markdown sopii erinomaisesti esimerkiksi README-tiedostoihin, dokumentaatio- ja raportointisivustoihin sekä laite- ja ympäristödokumentaatioon.

Markdownin etuja ovat:

  • helppo kirjoittaa
  • helppo lukea raakatekstinä
  • yhteensopiva GitHubin ja monien muiden työkalujen kanssa
  • hyvä yhdistelmä dokumentoinnin ja versionhallinnan kanssa

Markdownilla voidaan tehdä esimerkiksi otsikoita, luetteloita, linkkejä, taulukoita ja koodilohkoja, jotka ovat erittäin hyödyllisiä teknisissä dokumenteissa.

3. GitHub dokumentaatioalustana

GitHub toimii nykyään yleisesti dokumentaation julkaisu- ja hallintaympäristönä, erityisesti teknisessä kontekstissa. GitHub tarjoaa:

  • versionhallinnan
  • yhteisen repositorion
  • pull request -mekanismin
  • visuaalisen dokumentaation näkymän
  • tiedostojen ja linkkien hallinnan

GitHubin kautta voidaan ylläpitää myös koko laboratorioympäristön dokumentaatiota, yhteisiä käytäntöjä, kuvauksia ja raportteja. Tämä tekee dokumentaatiosta helposti löydettävää, vertaisarvioitavaa ja ylläpidettävää.

4. Documentation as Code

Documentation as Code tarkoittaa, että dokumentaatiota käsitellään kuten ohjelmistokoodia. Dokumentaatio:

  • tallennetaan Git-versionhallintaan
  • kirjoitetaan tekstimuodossa, esimerkiksi Markdownilla
  • tarkastetaan muutokset ennen hyväksymistä
  • vaiheistetaan ja dokumentoidaan muutoshistoria
  • voidaan automatisoida osittain

Tällainen lähestymistapa vähentää dokumentaation vanhentumista ja lisää yhteistä vastuuta tiedon ylläpidosta.

5. Single Source of Truth

Single Source of Truth (SSoT) tarkoittaa, että jokaiselle tiedolle on vain yksi virallinen lähde. Tämä on keskeinen periaate modernissa verkonhallinnassa.

Esimerkki ongelmasta:

  • Excel-taulukossa verkon IP-osoite on 10.0.0.1
  • verkkokaaviossa sama osoite on 10.0.0.10
  • laitteen konfiguraatiossa on taas toinen arvo

Kun sama tieto on eri paikoissa, dokumentaatio menettää luotettavuutensa. SSoT auttaa:

  • vähentämään ristiriitaisia arvoja
  • helpottamaan automaatiota
  • ylläpitämään ajantasaista tietoa
  • vähentämään virhettä ja käsityön tarvetta

Kurssin ympäristössä yksi virallinen lähde voi olla esimerkiksi Containerlab-topologiatiedosto, NetBoxin tietomalli tai yhteinen GitHub-repositorio.

6. Containerlab-topologian dokumentointi

Containerlab on työkalu, jolla voidaan mallintaa ja simuloida verkkoja helposti konfiguroituvissa ja toistettavissa ympäristöissä. Topologia on erittäin hyödyllinen dokumentaation lähde, koska se kuvaa:

  • laitteiden nimet
  • linkkien rakenteen
  • verkkojen segmentit
  • käyttöympäristön rakennetta
  • yhteyksiä laitteiden välillä

Containerlab-topologia on usein hyvä Single Source of Truth -lähde, koska siihen perustuvat myös konfigurointityökaluja, laboraatio-ympäristö ja dokumentaatio.

Topologian dokumentoinnin hyödyt:

  • ympäristö voidaan rakentaa uudelleen
  • verkko näkyy selvästi sekventiaalisesti
  • muutokset voidaan tehdä yhdessä määrittelemällä topologia
  • ympäristö on helpompi ymmärtää uudelle henkilölle

7. NetBox

NetBox on IP-verkkojen ja laitteiden tietomallin hallintaan suunniteltu työkalu. Se tarjoaa järjestetyn ja helposti käytettävän tavan dokumentoida verkon laitteita, IP-verkkoja, VLANeja, yhteyksiä ja hallintotietoja.

NetBoxin käyttö dokumentaation osana auttaa:

  • ylläpitämään laitekanta ja IP-osoitevaraukset
  • kirjaamaan VLAN- ja verkkojen hierarkian
  • vähentämään manuaalista ylläpitoa
  • tarjoamaan yhtenäisen tietolähteen useille järjestelmille

NetBoxin rooli verkon dokumentoinnissa on erityisen tärkeä modernissa automaation ja toimintamallin kehityksessä.

8. Mermaid-kaaviot

Mermaid on tekstipohjainen kaaviokieli, jolla voidaan luoda helposti verkko-, sekvenssi-, vuokaavioita ja muita diagrammeja suoraan dokumentaatioon. Se sopii hyvin GitHub- ja Markdown-dokumentaatioon.

Esimerkki Mermaid-kaaviosta:

graph TD
    A[Client] --> B[Router]
    B --> C[Switch]
    C --> D[Server]
    C --> E[Monitoring]

Mermaid helpottaa dokumentaation visualisointia ilman erillistä piirto-ohjelmaa. Tämä on erityisen hyödyllistä, kun dokumentaatiota halutaan ylläpitää versionhallinnassa ja GitHubissa.

9. Dokumentaation automatisointi

Dokumentaation automatisointi tarkoittaa, että tietoa tuotetaan osittain tai kokonaan ohjelmallisesti sen sijaan, että kaikki vaiheet tehdään manuaalisesti. Esimerkkejä automatisoinnista ovat:

  • laiteluetteloiden generointi
  • IP-osoitelistojen muodostus
  • topologian ja verkon kaavioiden luominen
  • monitorointi- ja raportointikohteiden generointi
  • verkon muutosten dokumentointi automatisoiduissa komentosarjoissa

Automatisointi parantaa dokumentaation laatua, nopeuttaa ylläpitoa ja vähentää virheiden määrää. Tavoite on, että dokumentaation ja reaalimaailman tila vastaavat toisiaan mahdollisimman hyvin.

10. Dokumentaation laatukriteerit

Dokumentaation merkitys perustuu siihen, että se on käytännöllistä ja ajantasaista. Hyvän dokumentaation kriteerejä ovat:

Kriteeri Selitys
Ajantasaisuus Dokumentaation tulee kuvata nykyistä ympäristöä.
Löydettävyys Dokumentaation tulee sijaita tunnetussa ja helposti löydettävässä paikassa.
Yksiselitteisyys Dokumentaation tulee olla selkeää ja niin tarkkaa, että se ei jätä epäselvyyksiä.
Toistettavuus Dokumentaation avulla ympäristö tulee pystyä rakentamaan uudelleen.
Riittävä tarkkuus Dokumentaation tulee olla tarpeeksi yksityiskohtainen mutta ei ylikompleksi.
Versionhallinta Kaikista muutoksista tulee jäädä jälki, jotta voidaan palata aiempiin versioihin.

Dokumentaation laatua voidaan parantaa myös noudattamalla yhteistä dokumentointistandardia, kuvaamalla tietolähteet ja dokumentoimalla ympäristön muutokset säännöllisesti.

Dokumentointi osana verkonhallintaa

Modernissa verkonhallinnassa dokumentaatio ei ole pelkkä lopputyö tai projektiraportti, vaan jatkuvasti ylläpidettävä osa infrastruktuuria. Hyvin toteutettu dokumentaatio:

  • nopeuttaa vianetsintää
  • helpottaa muutosten hallintaa
  • parantaa infrastruktuurin ymmärrettävyyttä
  • vähentää henkilösidonnaista tietoa
  • helpottaa automaation ja valvonnan integrointia

Kurssin ympäristössä tämä tarkoittaa, että dokumentaatio tuotetaan yhtenäisessä GitHub-pohjaisessa työskentelymallissa, jossa perustana ovat Containerlab-topologia, NetBoxin tietomalli ja versionhallinnassa ylläpidettävä kirjallinen dokumentaatio.

Yhteenveto

Verkon dokumentaatio ei rajoitu ainoastaan fyysisten piirrosten ja laitetietojen kirjoittamiseen. Moderni verkkodokumentaatio kattaa myös versionhallinnan, dokumentoinnin tekstimuodossa, GitHub-pohjaisen yhteistyön, Single Source of Truth -periaatteen, NetBoxin, Containerlab-topologian, Mermaid-kaaviot sekä dokumentaation automatisoinnin ja laadunvarmistuksen.

Näiden periaatteiden avulla verkko voidaan pitää ymmärrettävänä, ylläpidettävänä ja automaation tukemana koko elinkaarensa ajan.
